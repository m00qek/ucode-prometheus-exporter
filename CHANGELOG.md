# Changelog

What each release changes, for those who run the exporter and those who write collectors for it. The format is [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions are [semantic](https://semver.org/): before 1.0.0 a minor version may break things, and says so, marked **BREAKING** here.

## [Unreleased]

0.3.0 is the first release candidate for 1.0: the metric names and labels it has are those 1.0 keeps. Upgrading from 0.2.1 relabels or drops a few series, runs the jail as a user of its own, wants collectors of other packages to declare their ubus calls and to import the collector API by its new name, and moves the `prometheus-exporter` command to a package of its own: see [Upgrading the exporter](docs/how-to/upgrade.md#from-021-to-030).

### Added

- **[How to run the exporter on a small device](docs/how-to/small-device.md)**: the flash and RAM the packages take, `memory_limit`'s floor, and which collectors to leave out on 32 or 64 MB, with what each collector costs in [Performance on small routers](docs/explanation/performance.md#each-collector).
- `make bench`'s `floor:` cases find the least `memory_limit` under which uhttpd loads the handler and a scrape succeeds, and a budget holds it to `memory_limit`'s least, 8 MB: 7 MB with every collector on x86_64, 5 MB on a 32-bit MIPS 24Kc. Its `lazy:` cases time what a scrape loads where it needs it. `make bench-qemu` says what the packages add to the flash, and what the running service holds; `QEMU_MEMORY=64` runs it in 64 MB.
- **wifi writes whether each radio is up and whether it is disabled**, `node_wifi_radio_up{radio}` and `node_wifi_radio_disabled{radio}`: a radio is up while an interface of one of its networks is, as nl80211 and rtnetlink say, and disabled as the wireless config says. `OpenWrtWifiRadioDown` fires for a radio the wireless config enables and none of whose networks is up, and leaves out one disabled on purpose.
- **hwmon writes the limits of a chip's temperatures and a meter's average power**, as node_exporter does: `node_hwmon_temp_max_celsius` and `node_hwmon_temp_crit_celsius` from `tempN_max` and `tempN_crit` (a Wi-Fi radio's throttling thresholds, as mt76's), `node_hwmon_temp_alarm` from `tempN_alarm`, and `node_hwmon_power_average_watt` from `powerN_average`, each labeled `chip` and `sensor`.
- **thermal writes the state of each cooling device**, `node_cooling_device_cur_state{name,type}` and `node_cooling_device_max_state{name,type}`, as node_exporter's thermal_zone collector does beside the zones: a fan's step, a CPU's frequency step, a radio's transmit throttling. Its title is **Thermal zones and cooling devices**.
- **ethtool writes each device's driver and link as node_exporter's ethtool collector does**: `node_ethtool_info{bus_info,device,driver,expansion_rom_version,firmware_version,version}` from `ethtool -i`, and from `ethtool <device>` the ports and link modes it supports and advertises, `node_network_supported_port_info{device,type}`, `node_network_supported_speed_bytes{device,duplex,mode}` and `node_network_advertised_speed_bytes{device,duplex,mode}`, whether it supports and advertises autonegotiation, pause and asymmetric pause frames (`node_network_{autonegotiate,pause,asymmetricpause}_{supported,advertised}`), and `node_network_autonegotiate`. It runs ethtool three times a device where it ran it once. Its title is **Network drivers and links**.
- **unbound writes Unbound's extended statistics**, where its config has `extended-statistics: yes` (the UCI's `extended_stats`), as letsencrypt/unbound_exporter names them: the queries by type, class, opcode, flag and transport (`unbound_query_types_total{type}`, ...), the answers by rcode and DNSSEC result, the caches' entries and memory, the modules' memory, the unwanted queries and replies, and the recursion times as the histogram `unbound_response_time_seconds`; DNSCrypt's statistics, of an Unbound built with it, are left out. See [How to monitor Unbound](docs/how-to/unbound.md#extended-statistics).
- **filesystem writes each mount's inodes**, `node_filesystem_files` and `node_filesystem_files_free`, as node_exporter does and the Lua exporter did. luci's `getMountPoints` has no inode counts and the jail's statvfs() would see the jail's mounts, so the package installs an rpcd plugin of its own, the ubus object `prometheus-exporter.filesystem`, whose `mounts` gives each of the host's mounts with its type, read-only flag, sizes and inodes, from `/proc/mounts` and luci-base's statvfs(); installing the package reloads rpcd. It is all the collector calls. See [ubus object](docs/reference/ubus.md#prometheus-exporterfilesystem).
- **thermal writes each zone's critical trip point**, `node_thermal_zone_critical_celsius{zone,type}`, where the kernel shuts the system down: the lowest of the zone's trip points of type `critical`, as `node_thermal_zone_passive_celsius` is its passive one; node_exporter has none. The new alert `OpenWrtThermalZoneNearCritical` fires for a zone within 10 °C of it for a minute, and the router dashboards draw it with the zones.
- **dhcp_leases writes the size of each interface's DHCPv4 pool**, `node_openwrt_dhcp_pool_size{interface}`: the addresses from the `config dhcp` section's `start` for `limit` within the interface's subnet, as dnsmasq's init script ranges them, but the router's own; for each pool dnsmasq or odhcpd serve, not one with `ignore`, `dhcpv4 'disabled'` or `dynamicdhcp '0'`. node_exporter has no equivalent. `OpenWrtDhcpPoolNearlyExhausted` fires at 90% of it, where it fired at 135 leases, 90% of OpenWrt's default pool, whatever the pool; the router dashboards draw it with the leases.
- **The `pressure` collector, `ucode-prometheus-exporter-pressure`: pressure stall information**, as node_exporter's pressure collector has it, from `/proc/pressure`: `node_pressure_{cpu,io,memory}_waiting_seconds_total`, the time some task waited for the resource, and `node_pressure_{cpu,io,memory,irq}_stalled_seconds_total`, the time every task was stalled on it. It needs a kernel with `CONFIG_PSI`, which OpenWrt's kernels leave off, so it is not in the base package, where it would cost every scrape for nothing: it is a package of its own, in no group, and installing it turns it on.
- **The `interrupts` collector, `ucode-prometheus-exporter-interrupts`**: `node_interrupts_total{cpu,type,info,devices}` from `/proc/interrupts`, as node_exporter's interrupts collector labels it. node_exporter has it off by default, for its series, one per interrupt and CPU: here it is a package of its own, in no group, and installing it turns it on.
- **The collectors declare what their user needs besides their mounts**, in their `meta`: `ubus`, the objects and methods they call, `{ object: [ method ] }`, `hostapd.*` for hostapd's, methods a function of their options where one decides (wireguard's `uci get`, with `peer_names`); `capabilities` (nft-counters' `CAP_NET_ADMIN`); `groups` (unbound's); `proc_files` (nat_traffic's `/proc/net/nf_conntrack`). The loader checks them, and [Collectors](docs/reference/collectors.md) lists each collector's. See [Collector interface](docs/reference/collector-interface.md#meta).
- **The error codes `UBUS_NOT_ALLOWED` and `PERMISSION_DENIED`.** A ubus call a collector does not declare is refused without calling it, as root too, and `with_collector` fails a test whose collector makes one. What the system refuses the service's user fails `PERMISSION_DENIED`, saying what grants it, never nothing to observe: a capability its process lacks, a config or `/proc` file it may not read, a socket it may not connect to, a call ubusd refuses, or an object not found while ubusd has not loaded the service's ACL. See [Error codes](docs/reference/error-codes.md).
- `describe`'s `jail` has each collector's `ubus`, `capabilities`, `groups` and `proc_files`; `check` says the jail's user, its capabilities and its ubus ACL.
- **`out.batch(type, rows)` in the collector API**: families of one sample each, without labels, as meminfo and netstat write dozens, each row `[ name, help, value ]` recorded as `out[type](name, help)(null, value)` records it, without a writer made and called for each. And **`proc.rows(fs, path)`**: the fields of every line of a file, as `proc.fields()` gives them, with one look at a file of single spaces rather than one at each line. See [Collector interface](docs/reference/collector-interface.md).
- **The purity rule: a collector's top level only declares**, as it runs twice at load, in the probe's child and again in uhttpd's own process, which nothing guards. While a top level runs, at every load, `sleep`, `system`, `exit`, `print`, `printf`, `warn`, `trace`, `require`, `include`, `loadfile`, `loadstring`, `render` and `signal` refuse to run, and so do the collector API's `exposition` functions, which load the format: the collector is left out, `skipping collector: COLLECTOR_IMPURE (<module>: its top level called sleep(), which blocks the process: ...)`, before the call blocks, ends or writes to the process, loads code, or reaches a file, a program or a socket past the loader's text check. `prometheus-exporter collector check` and the tests read the module's text too, and fail a statement that is not a declaration, or a call of what is not one of ucode's functions that compute alone or the API's, with its line. The new error code `COLLECTOR_IMPURE`. See [Collector interface](docs/reference/collector-interface.md#the-top-level).
- **The devkit, `ucode-prometheus-exporter-devkit`: what a collector of another package is written and tested with.** Its modules, `prometheus.exporter.devkit.*`, are what the exporter's own collectors are tested with: `with_collector`, which runs a collector as a scrape does in the filesystem the service's jail gives it and fails a test whose collector touches what its `meta` does not declare; `assert_module` and `module_problems`, what the loader and `collector check` refuse of a module's text; the mocks' proxies for ubus, rtnl, nl80211 and socket; programs (`commands`), fixtures (`fixtures.reader`) and rpcd's `rc`. It depends on `ucode-utest`, and is for a development machine or a CI image. With it, a **template collector package**, `devkit/template` in the source: a Makefile for the SDK, a collector, its test and fixtures; `make template-package` builds it, `make package-check` runs its tests on the installed devkit, and `make e2e` installs it beside the exporter and scrapes it. See [How to write a collector in your own package](docs/how-to/collector-package.md) and [The devkit](docs/reference/devkit.md).
- **The collector API, `prometheus.exporter`, is frozen for 1.0**: what it exports, the recorder, `meta`, `deps`, the rules a module is loaded by, and the devkit; only a major version breaks them from here. See [About versions](docs/explanation/versions.md#the-collector-api).
- **Alerting rules and dashboards, in `monitoring/`.** Rules for Prometheus and vmalert on the exporter's own health, `OpenWrtExporterDown`, `...CollectorFailing` (with its failures by error code), `...CollectorQuarantined`, `...DeadlineSkips`, `...ProgramTimeouts`, `...AuthFailures` and `...ScrapeSlow`, and on a router's basics: the connection table, memory, filesystems' space and inodes, temperatures at their chip's maximum or critical, a throttling thermal zone, the WAN, a Wi-Fi radio enabled and down, the clock, the DHCP pool; each with a summary, a description and a severity, its threshold in its expression, and tests. No rule names a job: each takes the targets that write `ucode_prometheus_exporter_build_info`, whatever their jobs are called, and leaves a node_exporter's alone; `OpenWrtExporterDown` fires for a target down that wrote it in the last 7 days. Two dashboards, **OpenWrt router** and **OpenWrt exporter health**, for Grafana and for Perses, their data source, job and instance variables, which list the exporter's targets alone, a panel whose collector is not installed showing no data. `make monitoring-check`, in CI, holds every metric and label they name to the reference, refuses a rule that matches a job or an instance unless a comment of it allows it, runs `promtool` and `vmalert` on the rules and their tests and `percli lint` on the Perses dashboards; `make monitoring-lab` runs them on the lab, in Prometheus, Grafana and Perses. See [How to monitor a router with the bundled dashboards and alerts](docs/how-to/dashboards-and-alerts.md).
- **[Migrate from prometheus-node-exporter-lua/-ucode](docs/reference/migration.md)**: every package and metric family of the feed's Lua and ucode exporters, and this exporter's for each, same, renamed, relabeled or missing (with why, and what to use); PromQL rewrites of the common queries; a `metric_relabel_configs` that renames the old families whose labels and values are unchanged, for a fleet that moves router by router; and what the configuration import takes over and what it does not. `make docs-gen` writes it from the feed exporters' sources, which the new `make feed-inventory` reads from openwrt/packages into `docs/gen/feed-exporters.json`, and refuses a family of theirs it has no row for, or a row that names a family no collector writes. [How to move from the feed's exporters](docs/how-to/migrate-from-feed.md) has a checklist.
- **[What happens when a collector breaks](docs/explanation/when-a-collector-breaks.md)**: this exporter and the Lua one, measured, as a real Prometheus server scrapes them, when a ubus daemon hangs, a program never exits, a label is not UTF-8, and a slow router's conntrack table holds 20,000 connections. `make failure-demo` runs it again, not in CI.
- **The `agh` collector, `ucode-prometheus-exporter-agh`: AdGuard Home**, from its HTTP API on the router, `/control/status` and `/control/stats`, read without a login: `adguard_up`, `adguard_build_info{version}`, `adguard_running`, `adguard_protection_enabled`, `adguard_start_time_seconds`, and the totals of its statistics window, gauges and not counters, since they fall as the window moves: `adguard_stats_window_seconds`, `adguard_stats_dns_queries`, `adguard_stats_blocked_filtering`, `adguard_stats_replaced_{safebrowsing,safesearch,parental}` and `adguard_stats_avg_processing_time_seconds`. Never the domains, clients or upstreams it ranks. Its options `address`, an address of the router (127.0.0.1), and `port` (8080); it depends on `ucode-mod-socket`, not on AdGuard Home, and has nothing to observe where AdGuard Home is disabled or not installed. A package of its own, in no group. See [How to monitor AdGuard Home](docs/how-to/adguard-home.md).
- **The `mmc` collector, `ucode-prometheus-exporter-mmc`: the health an eMMC reports of itself**, from `/sys/class/mmc_host`, as eMMC 5.0 and later have it: `node_mmc_life_time_step{device,type}`, the life time used of its type A (SLC) and B (MLC) memory as it estimates it, in steps of 10% (1 is 0-10% used, 10 is 90-100%, 11 past its estimated life); `node_mmc_pre_eol_state{device,state}`, its reserved blocks, `normal`, `warning` (80% consumed) or `urgent`, one series a state; and `node_mmc_info{device,name,manfid,oemid,rev}`. A field the eMMC leaves undefined (0) is left out, and an SD card, which has neither, or an older eMMC, is nothing to observe. A package of its own, in no group. See [Collectors](docs/reference/collectors.md#mmc).
- **`deps.socket.tcp_request(address, port, message, timeout_ms)` in the collector API**: the whole reply of a TCP port of the device itself, as `unix_request` gives a Unix socket's, each wait bounded by `timeout_ms`. It binds to the address before it connects, so an address that is not the router's own fails `SOCKET_FAILED` without connecting: whoever sets a collector's address can point it at a port of the router, never at another host. And the option datatype `ipaddr`, an IPv4 or IPv6 address, which the core checks as LuCI does (`IPADDR`). See [Collector interface](docs/reference/collector-interface.md#needs).

### Changed

- **rpcd holds of the service's ubus object only what the collectors call**, `wireless`, `wireguard_peers` and `time_daemons`, and compiles the rest, which LuCI calls, when one of its methods is called, letting go of it 120 s after the last. rpcd collects its plugin's garbage after every call, a pass over all the plugin holds: holding every module of the object, 0.7 MB, each call of the collectors' methods made the next call to rpcd, by the collector or by any other, wait some 1.5 ms in the devenv and 15 to 20 ms on an access point, where it now holds 0.1 MB and waits 0.03 ms. A page of the LuCI app compiles the rest once, some 25 ms in the devenv. The benchmark's `rpcd:` cases measure what the plugin holds and each of the three methods with rpcd's collection after it, and budgets hold them. See [Performance on small routers](docs/explanation/performance.md#the-ubus-objects-sources).
- **uhttpd loads, when it starts, the native modules its enabled collectors need, and zlib while `compress` is on**: ubus, rtnl and nl80211 where an enabled collector declares one in `meta.needs`, so that no scrape loads them again, which each scrape's child did, some 4.6 ms of an access point's scrape on a Cortex-A53 and 7 ms on a 500-MIPS 24Kc. Each is loaded in the probe's child first, as the collectors are: one that crashes as it loads costs that child, is logged (`native module '<name>' did not load in a process of its own`), and is left to the scrapes, where a crash costs the collector that needs it. uhttpd holds some 0.1 MB more with them. Basic auth's modules, the exposition parser and socket are still loaded where they are needed, and basic auth still denies every request should its module not load. See [Performance on small routers](docs/explanation/performance.md#natives-at-start).
- **BREAKING for collectors: the `exporter` capability is the serving process alone**, `process()`, `fds()` and `system()`: `counters()` and `samples()` are gone, as the scrape writes what they gave; and no collector writes a `ucode_prometheus_exporter_*` family, a collector that needs `exporter` included (`FAMILY_CONFLICT`). See [Collector interface](docs/reference/collector-interface.md#needs).
- **Smaller packages: the code installs without comments.** The build strips every comment of the ucode and JavaScript files it installs, keeping a newline for each line it empties, so an error's line on the device is the line in the source; and the sources keep no explanatory comments, only a typed one-line JSDoc on each exported symbol, their explanation moved to the docs ([About the implementation](docs/explanation/internals.md)). The base package installs 264 KiB, where it installed 554, its `.apk` is 80 KiB where it was 171, and on a JFFS2 overlay it takes 119 KiB where it took 250; the LuCI app 54 KiB where 73, the command line 10 where 17, a collector 1 to 12 where 2 to 16. On a 1.6 MB JFFS2 overlay, the base package, the LuCI app and three collectors take 296 KiB, where they took 452, and upgrade in place. uhttpd holds 30 kB less of the source it compiled. `make test` checks that every installed ucode file, stripped, compiles to the same bytecode as its source, `make package-check` the installed files themselves, `make browser` the LuCI app's tokens, and `make same-code REV=main` that a change to comments changed nothing else. See [Performance on small routers](docs/explanation/performance.md#flash).
- **BREAKING: snmp6 exports 13 fields of each device by default**, where it wrote every one of `/proc/net/dev_snmp6/<device>`, some 70: 130 series on a router of 10 devices where it wrote 712. It keeps the device's octets, ICMP messages and the ICMP errors it received (node_exporter's netstat defaults, by device), the datagrams it forwarded, discarded or found no route for, and those it received with a bad header, a destination not its own or too big to forward. `node_snmp6_ifindex` is among those left out: netclass's `node_network_iface_id` is the same index. The new option `fields`, a regular expression of `<Protocol>_<Field>` as netstat's is, takes others: `option fields '.*'` exports every one, as before. See [Collectors](docs/reference/collectors.md#snmp6).
- **BREAKING: nat_traffic writes a series per host, `node_nat_traffic_bytes{host}`**, where it wrote one per pair of addresses, `{src,dst}`, which came and went with every connection: 14 series for a router's 160 connections where it wrote 75, and on a busy router a few dozen where it wrote thousands, a new set every few minutes. A connection's host is its end on this side of the router, as the routes say, read from rtnl at each scrape and kept as a set of prefixes for each length, so that an address is a few lookups (see [Performance on small routers](docs/explanation/performance.md#where-it-still-bites-nat_traffic)): an address of the router's own, or one on-link to an interface without a default route, a LAN's subnet or a delegated IPv6 prefix. For one destination-NATed (a port forward) it is the LAN host it reaches, else the source, else the destination: a LAN client's connection out, or the router's own, is the client's or the router's; one from the internet that the firewall accepts without NAT is the router's WAN address's when it is to the router (a ping, an open port), and the LAN host's when it is ICMPv6 to its global address. A connection with neither end on this side is written as one series, `host="other"`. So a LAN bounds them, whatever the peers and the scanners; and past the 2048 hosts with the most bytes the rest are `host="other"` too, logged. The new option `peers`, off by default, labels each host's bytes by the address at the other end too, `{host,peer}`, as many series as before, which a Prometheus server keeps for hours each; past 16384 pairs, the rest are `peer="other"` of their host, logged. See [Collectors](docs/reference/collectors.md#nat_traffic).
- **A scrape costs less besides its collectors.** The collectors' child process goes through the scrape's plan itself, and writes each collector's start and run to a file the scrape reads while the child goes on, in one write a collector, where each collector was three messages over a pipe and two wakeups of the scrape; who owns each family is checked all at once; the scrape's own four samples of each collector are written as text; and the ledger, the config's collector sections and the scrape's order are each read or worked out once a scrape. Through uhttpd, a scrape of the base collectors spends 118 ms besides them on QEMU's 500-MIPS 24Kc, where it spent 161, and of every collector 378 ms, where it spent 518; a collector that writes nothing costs a scrape 0.89 ms on a Cortex-A53 access point, where it cost 1.5. The reply is the same, byte for byte. See [Performance on small routers](docs/explanation/performance.md#in-030).
- **uhttpd holds a quarter less.** Basic auth's hash formats and the ledger's error codes were regexes with counts, which musl compiles into a copy of what they count for each, 400 kB held for as long as uhttpd runs; the loader, the jail's rules and the import scanner, which serve no scrape, are compiled in the probe's child alone, which checks each collector there; and rtnl, nl80211 and socket are loaded only when a loaded collector needs them. With the base collectors, the handler holds 1.48 MB, where it held 2.01 MB, on a Cortex-A53; with an access point's 19 collectors, uhttpd's private memory is 1.88 MB, where it was 2.46 MB. `make bench`'s new `rest:` cases measure it, and a budget holds it.
- **uhttpd holds less again, and loads what a scrape needs now and then where it needs it.** The exposition parser is loaded the first time a collector parses; basic auth's module, crypt and ucode-mod-digest only where basic auth is set, and should they not load every request is denied; and what the service grants its user when it starts moved to a module only `jail.uc` loads. The service's uhttpd holds 1.74 MB with an access point's 19 collectors in the devenv's procd container, where it held 2.07 MB, and 1.63 MB with the base collectors, where it held 1.90; an access point's scrape loads 4.6 ms of them on a Cortex-A53, and one with unbound 10 ms of parser more. See [Performance on small routers](docs/explanation/performance.md#at-rest).
- **BREAKING: the jail no longer runs as root.** With the ubus socket in the jail, ubusd let it call every object, as root; and it read every file it had, and had every capability. uhttpd now runs in the jail as the user and group `prometheus-exporter`, which the package makes, with no new privileges, and the service grants it, when it starts, what the enabled collectors declare, and takes back what the others do: a ubus ACL of their calls, which ubusd reads through a link the package installs in `/usr/share/acl.d`; their capabilities, in every set, and `CAP_NET_BIND_SERVICE` for a port under 1024; membership of their groups; read access for its group to their proc files and to the configs the jail mounts. The ACL is written for the enabled collectors, not installed for all of them, as ubusd's ACL cannot narrow a call's arguments, and `file read` and `uci get` read anything. Basic auth's file is the group's to read; the TLS key and certificate are read from copies made for the group at each start, removed when it stops. `check`, `status` and the command line's scrape run as the same user. The `watch` instance stays root's. textfile's files must be readable by the user. See [The jail](docs/reference/jail.md#the-services-user) and [About the security model](docs/explanation/security.md#not-root).
- **BREAKING for collectors: the collector API is `prometheus.exporter`, and collectors are installed under `/usr/share/ucode/prometheus/collectors/`.** A collector imports `prometheus.exporter`, with the same names, where it imported `prometheus_exporter.api`, and the loader refuses the old name as any other module; its package installs it to `/usr/share/ucode/prometheus/collectors/`, where it installed it to `/usr/share/ucode/prometheus_exporter/collectors/`, which the exporter no longer reads; its tests import it as `prometheus.collectors.<module>`, and the devkit as `prometheus.exporter.devkit.*`, its proxies under `/usr/share/ucode/prometheus/exporter/devkit/proxies/`. The exporter's own modules are `prometheus.exporter.<module>`, under `/usr/share/ucode/prometheus/exporter/`, and the upgrade removes what the exporter's packages installed under `/usr/share/ucode/prometheus_exporter/`: a collector of another package built for 0.2.1, or for an earlier build of 0.3, stays there and is not loaded until its package is rebuilt. See [Upgrading the exporter](docs/how-to/upgrade.md#from-021-to-030), which has a `sed` for its source.
- **BREAKING: a collector that needs ubus must declare its calls** (`meta.ubus`): the loader refuses one without them.
- **BREAKING: the `prometheus-exporter` command is a package of its own, `ucode-prometheus-exporter-cli`**, the only one that depends on `ucode-docopt`. The base package no longer installs `/usr/bin/prometheus-exporter`, and the service needs none of it: the init script's check, and `service prometheus-exporter check`, are the base package's `/usr/libexec/prometheus-exporter/check.uc`, which the command's `check` runs too, and LuCI and the ubus object set basic auth's password. An upgrade leaves a device without the command: a script or cron job that runs it (`scrape`, `hash-password`) needs `apk add ucode-prometheus-exporter-cli`. See [Upgrading the exporter](docs/how-to/upgrade.md#from-021-to-030).
- **LuCI changes basic auth's password with a button of its own, Change password**, apart from Save, Save & Apply and Revert, as LuCI's own router password is: a dialog takes the new password twice, says that it applies at once and that every scraper must be given it, and hands it to `set_password`, which saves its hash and reloads the service. The password was a field of the form, which Save handed to `set_password`, applying it before the rest. The row says whether a password is set, never the hash; Change password needs the TLS certificate and key, and **Remove password**, which removes the saved hash, an empty user. The app's ACL is 0.2.1's: `set_password` to a login that may write, nothing of the hash's config.
- **The collectors an access point runs cost less**, their output the same, byte for byte, on the fixtures. netstat looks for the fields its default takes in each section's names, where it checked each of the kernel's 400 or so, and splits a line of `/proc/net/snmp6` on its tab, where it took a regex; netclass reads 9 to 11 of a link's sysfs files, where it read 14, and takes the rest from the link dump or from what tells the same; the exporter collector reads the auxiliary vector a word at a time and finds `/proc/stat`'s btime line with an index(); vmstat checks its default without a regex; meminfo, netstat, vmstat and the exporter collector record their families of one sample in a batch; and a family's name valid as it is is taken after one match. On a Cortex-A53 access point (`make bench-device`), netstat takes 15 ms where it took 29, netclass 90 ms of 50 links where it took 109, netdev 42 ms where it took 51, the exporter collector 6.6 ms where it took 9.3, and vmstat 5.4 ms where it took 7.7. See [Performance on small routers](docs/explanation/performance.md#collectors-in-030).
- **BREAKING: a collector whose top level does more than declare is left out**, `COLLECTOR_IMPURE`: one that calls `sleep`, `exit`, `print` or loads code as it loads, which 0.2.1 loaded, and ran again in uhttpd's process unguarded. Every collector of the exporter's packages only declares. See [Upgrading the exporter](docs/how-to/upgrade.md#from-021-to-030).
- **The tests' collector helper is the devkit's**, for those with a branch of the tree: `test/context.uc` is `prometheus.exporter.devkit.collector`, `test/lib/commands.uc` and `test/lib/rc.uc` are `prometheus.exporter.devkit.commands` and `.rc`, and `test/proxies/` is `src/prometheus/exporter/devkit/proxies/`. A test imports them by those names.

### Fixed

- **The exporter's counters are in every scrape, those the deadline cut short included.** The `exporter` collector wrote `ucode_prometheus_exporter_deadline_skips_total`, which `OpenWrtExporterDeadlineSkips` reads, and the other counters of the instance's ledger; it ran after every other collector, so the deadline left it out first, and the counters had gaps in exactly the scrapes they should count. The scrape now writes them itself, with each collector's samples, once its collectors have run, while the exporter collector is selected, whatever the deadline, a breaker or a crash did to it; this scrape's skips are counted in them. The exporter collector writes the `process_*` families, and no longer runs last. See [Metrics](docs/reference/metrics.md#scrape).
- **A collector's top level can no longer change what the others, and every later scrape, see.** The guard of the top level undid only the functions it refused: a top level that wrote over a global, `global.sort = ...`, or over what the collector API exports, `Result.ok = ...`, which every collector loaded with it shares, left it so in uhttpd for as long as it ran. What the API exports, `Result`, `errors`, `services`, `proc` and `exposition`, and a Result's prototype, are now constant, as module namespaces are in ucode: writing over one fails, and at the top level the collector is left out, `COLLECTOR_IMPURE`. The global scope is put back as it was once a top level has run, and a module that changed it is left out, naming what it changed. `collector check` no longer lets the top level call `proto()`, which reaches a Result's prototype. See [Collector interface](docs/reference/collector-interface.md#the-top-level).
- **A collector whose `meta` is long is no longer reported as hung at load.** The probe's child sent what it checked of a module, the meta's JSON, in one message over uloop's pipe, which the reader loses when it is not there whole: a collector of another package with many options and long help, past 4 kB, could be logged `hung at load: still loading after 5 s` and left out, and past 64 kB on a single-core router always was. The child now sends it in parts that each cross whole.
- **A scrape asked to stop while its collectors run ends cleanly, and Ctrl-C stops `prometheus-exporter scrape`.** A SIGTERM or SIGINT ended the scrape's wait for the collectors' child with its plan half done: the child ran on with no limit, the scrape crashed on a collector it had no run of, and the next scrape blamed the collector the progress file named, quarantining it. The scrape now kills the child and every process under it, blames no collector, removes its progress file, and ends as the signal would have ended it, logging `asked to stop (signal <n>) while it ran the collectors: stopping`; so do `check` and the ubus object's `status`.
- **A collector that ends while the scrape stops its child keeps its run, and the next collector runs.** Stopping the collectors' child takes a few milliseconds, its processes found and killed; a collector that ended in them, just past its limit, had its run and the next collector's start written first, and the scrape gave the next collector the first one's cancelled run: the reply had the first collector's own series twice and none of the next one's, which never ran, and the first one's breaker counted a failure for a run that was served. Each run now goes to the collector it names, and the next collector runs again in a new child.
- **The scrape holds the collectors' child process to its deadline again, whatever the child says.** Since the child goes through the scrape's plan itself, the limit the scrape stopped a collector at was the one the child gave: a collector that wrote over what the plan keeps in that process, by mistake, could have it give a limit past the deadline, or none, and run on past it, as nothing held it. The scrape now stops the child at the deadline at the latest, and a child that runs past it with no collector started a tenth of a second later; it then forks no other, serves the runs the child finished, and leaves the rest out with `SCRAPE_DEADLINE`, logging `the process running the collectors ran past the scrape's deadline`. A child that keeps to its limits is stopped as before, and the reply is the same. See [About the architecture](docs/explanation/architecture.md#a-process-of-its-own).
- **An upgrade of several packages no longer leaves the service serving no collector.** uhttpd runs the handler before its own event loop, and the handler loads its collectors in a child process first, waiting for it in a loop of uloop's, which takes SIGTERM: when procd stopped an instance still loading them, as a reload between the packages of an upgrade does, the wait ended, every collector was taken for one that changed since it was checked (`skipping collector: <module>: not what it was when it was checked, in a process of its own`), and uhttpd's own loop forgot the signal, so the instance served none until procd killed it 5 s later. The handler now ends when asked to stop while it loads them; and a module whose file changed between its check and its load, as an upgrade's next package can make it, is checked and loaded again, logged at info, and left out only when it changed at each of three checks. See [Log messages](docs/reference/log-messages.md#the-handler).
- **A FIFO in the state directory could hang rpcd, and a link there had root open any file.** The ubus object read the service's ledger, as root, at every call, and `check` at every start and reload, from the state directory the service's user owns: a FIFO in place of the ledger blocked rpcd, and every object it serves, for good. The ledger is now read only by `status` and the full `check`, and only as a regular file of the directory's owner with one link and at most 32 KiB, opened so that a FIFO does not block it, and left unread when what was opened is not what was looked at. See [The jail](docs/reference/jail.md#state).
- **While filesystem was enabled, the service's user could have rpcd read any file as root.** Its ACL allowed rpcd's `file read`, which reads whatever path it is given, and checks no session for a caller that sends none: `/etc/shadow`, the basic auth hash, `/etc/uhttpd.key`, the WireGuard and Wi-Fi keys. filesystem now asks the package's own object alone, whose `mounts` gives the type and read-only flag of each mount with its sizes, and takes no arguments; the ACL no longer allows `file read`, nor luci's `getMountPoints`. See [About the security model](docs/explanation/security.md#not-root).
- **While wifi or hostapd_stations was enabled, the service's user could read every Wi-Fi key.** netifd's `network.wireless status`, which their ACL allowed, holds each network's config, its `key`, `sae_password` and `auth_secret` with it. So did rpcd's `uci get`, which wireguard's `peer_names` had the ACL allow, read any config, the basic auth hash's and the WireGuard private keys among them; and procd's `service list`, which timesync's did, every service's command line and environment. The service's ubus object now reads what they need as root and gives the collectors the fields they read alone, in three methods that take no arguments: `wireless`, the radios and their networks without a key, from the wireless config, each network with the interface netifd names it; `wireguard_peers`, each peer's public key and description, from the network config; and `time_daemons`, whether busybox ntpd and chronyd run, from procd's `service list`. None of them runs a program or holds rpcd: they read uci and sysfs in rpcd's own process, and procd is asked without waiting on it, at most 3 s. wifi takes which interfaces are there, and up, from nl80211 and rtnetlink. The ACL allows those, and none of the calls they replace. See [About the security model](docs/explanation/security.md#what-the-services-user-reaches-over-ubus).
- **BREAKING: `cert` and `key` could have root copy any file into the jail.** Whoever may write the configuration, as a LuCI login allowed this app alone, could set them to `/etc/shadow`, which `jail.uc --make` copied, as root, for the service's group to read; or to `/dev/zero`, which it read until the router ran out of memory, and a FIFO hung the init script. They now take a file under `/etc/ssl`, `/etc/acme` or `/etc/prometheus-exporter`, or uhttpd's own `/etc/uhttpd.*`, and refuse any other with the new problem code `TLS_PATH`; there, a file that is not regular, is larger than 64 KiB, or whose links lead out of those places, with `TLS_FILE`. LuCI, `validate`, `check`, start and reload refuse it; `jail.uc --make` checks again and reads at most 64 KiB; and the init script serves HTTPS only from the copies it made, and has procd watch those, not the files the config names. See [About the security model](docs/explanation/security.md#not-root).
- **Root made and mounted textfile's directory through what another user put in `/tmp`.** It made each directory of the path that was not there, following links, under the world-writable `/tmp`, which `/var` is on OpenWrt: a user that started before the service could make `/var/prometheus` its own, or a link to a directory it chose, and root mounted it into the jail. The service now walks the path from `/` first: each directory must be root's and writable by no one else unless sticky, and a link root's; it makes what is not there root's and 0755, and checks it again. A path that fails is neither made nor mounted, logged at err and warned of by `check`. And `owned_directory` refuses a directory under `/var/run` or `/tmp/run`, every service's run directory, the exporter's own included. See [The jail](docs/reference/jail.md#owned-paths).
- **What the service granted outlived what declared it.** A collector package removed left its configs readable by the service's group, `/proc/net/nf_conntrack` too, and the user a member of `unbound`; stopping or disabling the service, or removing it, left them all, and basic auth's `uhttpd.conf`. A start or reload now takes back whatever no enabled collector declares, giving each file the group and mode it had, which it records in `/var/run/prometheus-exporter/granted.json`, or root's group where it has no record, as after a reboot; and takes the user out of every group none declares. A stop, `enabled 0` and the package's removal, which now stops the service rather than leave its instance running without its files, take back all of it, and remove `uhttpd.conf`; removing a collector package with the service neither enabled nor running does too. See [The jail](docs/reference/jail.md#the-services-user).
- **A read-only login could run any number of scrapes at once, as root.** Each call of the ubus object's `status` forked its helper for a full scrape of up to 60 s, however many ran already: a status page refreshed again and again, or a script, piled them up. One now runs at a time, and a call made meanwhile waits for it and gets its reply. See [ubus object](docs/reference/ubus.md#status).
- **A NUL byte no longer gets past the recorder's checks.** ucode's regexes, and its `replace()`, stop at the first NUL, so whatever followed one in a label value, a HELP text or a family's name was checked by nothing: a quote, a newline or a byte that is not UTF-8 after it went out as it was, and a name with a NUL and a newline wrote lines of its own. Prometheus then refused the whole scrape, every collector's samples with it. The format has no escape for a NUL, so the recorder now refuses one in a label value, a HELP text or a family's name, with `EXPOSITION_INVALID`, as it refuses a value that is not UTF-8: the collector fails and its samples are left out, the others' served. The exposition parser, which textfile and unbound read with, refuses a line with one, naming it.
- **A label named `__name__`, or anything else that starts with `__`, is refused**, as Prometheus reserves those names: one of `__name__` gave a sample two, its family's and its own, and Prometheus refused the whole scrape for it. The recorder refuses such a label, as written or once sanitized (`--x` is `__x`), with `EXPOSITION_INVALID`, and the exposition parser a line with one, so a textfile `*.prom` file with one is left out and logged.
- **Taking over the feed's ucode exporter's settings no longer leaves a configuration the service refuses.** Its `config collector` sections were copied option for option, so one value this exporter refuses, as wifi's `stations 'maybe'`, made the configuration invalid, and the service did not start until it was changed. Each option is now checked as the service checks it, against the collector installed: a value it refuses is left at its default, and an option it has not is left out, each logged. A collector not installed yet, as the script runs when the base package is installed, before the packages installed with it, is checked against what the feed's exporter had of it (wifi's `stations`) and the options every collector has (`enabled`, `budget`, `max_samples`). See [Migrate from prometheus-node-exporter-lua/-ucode](docs/reference/migration.md#configuration).
- **ethtool no longer writes a series twice** where a driver reports a statistic of node_exporter's seven common ones and the same with `_total`, as `rx_bytes` and `rx_bytes_total`: both were written as `node_ethtool_received_bytes_total{device}`, as it checked the names two statistics share before it gave the seven theirs. It now leaves out both, as it leaves out statistics whose names are one once sanitized.

## [0.2.1] - 2026-10-08

Upgrading from 0.2.0 relabels the series of three collectors, moves basic auth's hash to a config of its own, and refuses a few values and collectors 0.2.0 took: see [Upgrading the exporter](https://m00qek.github.io/ucode-prometheus-exporter/0.2/how-to/upgrade/#from-020-to-021).

### Added

- **`u32()` and `u16()` in the collector API**: a ubus integer a daemon sent unsigned (`blobmsg_add_u32()`, `blobmsg_add_u16()`), which ucode's ubus gives signed, as the value the daemon meant. See [Collector interface](docs/reference/collector-interface.md#the-collector-api).
- **A cap on the samples of a whole reply**, the new main option `max_scrape_samples`, 200,000 by default: a collector whose samples would go past it fails with `SAMPLE_LIMIT`, and one left once it is reached is not run; neither counts against its breaker. Only each collector's `max_samples` bounded a reply before, so a reply could run the scrape out of memory, and the next scrape blamed the collector that happened to be running. LuCI's Limits tab has it as **Reply sample limit**.
- The ubus object's `password`, which says whether a hash of basic auth's password is saved, and `set_password`, which hashes a password, saves the hash and has the service reload; LuCI's ACL grants them in place of `hash_password`.

### Changed

- **BREAKING: basic auth's hash has a config of its own, `/etc/config/prometheus-exporter-auth`.** LuCI's read ACL granted the exporter's config, so a login allowed only to look at the settings could read the hash through rpcd's `uci` object, and guess the password offline. The hash moves to a config the package installs, mode 0600, which the app's ACL does not grant and the jail does not mount; LuCI asks `password` whether one is saved and saves a new one through `set_password`, which takes effect at once. The upgrade moves a hash from the main section, and logs it; `check` warns of one left there, which is ignored. A hash without `auth_user` is no basic auth now, not an invalid configuration, and the code `AUTH_NEEDS_USER` is gone. See [How to serve HTTPS with basic auth](docs/how-to/https-basic-auth.md).
- **BREAKING: textfile's `directory` must be under `/var`, `/tmp` or `/etc/prometheus-exporter`.** The service makes that directory as root and mounts it in its jail, and refused only a short list of directories every service shares: anyone who could write the exporter's configuration could have it make and mount most others. A directory elsewhere is now refused, with the new code `OWNED_DIRECTORY`, by `check`, a reload, the ubus object's `validate` and LuCI, and the jail neither makes nor mounts an owned path outside them. Move one under `/srv` or `/mnt` to `/etc/prometheus-exporter/...` before upgrading. A collector's option that names an owned path takes the new datatype `owned_directory`. See [The jail](docs/reference/jail.md#owned-paths).
- **The jail has the ubus socket only while an enabled collector needs ubus.** The jail runs as root, and ubusd lets root call any object: a router whose enabled collectors read files and netlink alone now runs the exporter without ubus, and so do `check`, the ubus object's `status` and `prometheus-exporter scrape`. The base package's `timesync` and `openwrt_interfaces` need it; disable both and the jail has none. A collector whose programs call ubus declares `ubus` in `meta.needs`. `jail.uc` prints the service's own mounts with the collectors', the ubus socket among them while one needs it, and the init script mounts what it prints. See [The jail](docs/reference/jail.md#what-a-collector-gets).
- uhttpd runs at most 3 requests at once over at most 10 connections (`-n 3 -N 10`), where it took its defaults of 3 and 100: one or two scrapers need no more, and a client that reaches the port can queue fewer scrapes behind it. The port is meant for the scrapers alone: [How to listen on the LAN](docs/how-to/listen-on-lan.md#keep-it-to-the-scrapers) has the firewall rules that keep it so, and [HTTP endpoint](docs/reference/http.md#keep-alive) says why keep-alive is 70 seconds.
- **BREAKING: nat_traffic labels an IPv6 address compressed**, as RFC 5952 writes it and every other collector labels it: `src="2001:db8:0:1::e157"`, where it had the kernel's `2001:0db8:0000:0001:0000:0000:0000:e157`, which joined nothing. Each address is compressed once, and an IPv4 one not at all: a table of 20,000 connections, a fifth of them IPv6, takes about 5% longer.
- **BREAKING: netstat exports node_exporter's default fields only**, those its `--collector.netstat.fields` keeps: the errors, IP forwarding and octets, ICMP messages, TCP's connections, segments, retransmissions, listen queue and SYN cookies, and UDP's datagrams and buffer errors, 42 series on a router where it wrote about 400. The new option `fields`, a regular expression of `<Section>_<Field>` as vmstat's `fields` is, takes others: `option fields '.*'` exports every one, as before.
- **BREAKING: hostapd_stations labels each station's series by `vif` and `station` alone.** `ssid`, `bssid`, `encryption`, `frequency` and `channel` moved off every `hostapd_station_*` series to the new `hostapd_station_info{vif,station,ssid,bssid,encryption,frequency,channel}`, one per station: a channel change (DFS, ACS) started a new series of every station's counters. A query that selected by them joins the info metric: `hostapd_station_signal_dbm * on (vif, station) group_left (ssid) hostapd_station_info`.
- **A sample with labels costs a quarter less, and a collector less besides it.** The labels each sample must now give as an object, checked as they are written, are written a lookup and a concatenation a label once the recorder has written their names, when their values need nothing escaped or read as UTF-8, where each sample called a function that split the set's text: a sample of two labels takes 5.2 µs in the devenv where it took 7.6, and 235 µs on QEMU's 500-MIPS 24Kc where it took 318. nat_traffic takes 8.2 s there for 20,000 connections, where it took 9.7, and 0.21 s in the devenv, where it took 0.25; cpu 23 ms where it took 28; netstat, which checks node_exporter's default fields with lookups rather than musl's regexec, 84 ms where it took 135. A collector without a section of its own is given its defaults unchecked, and the recorder's module is compiled first in the handler's program, where ucode makes its closures cheapest: a scrape costs 4.3 ms a collector besides it on the 24Kc, where it cost 5.0. See [Performance on small routers](docs/explanation/performance.md#samples-and-collectors).

### Fixed

- loadavg left out an average of `/proc/loadavg` that was not a number, and succeeded without it; it fails with `SOURCE_INVALID`, writing none.
- `node_wifi_network_quality_ratio` went past 1 for stations stronger than -40 dBm, and below 0 under -110 dBm; it is kept from 0 to 1.
- wifi's option `stations` off also left out `node_wifi_stations`, how many stations each interface has, which is no per-station series; it is written either way.
- **selinux reported SELinux off in the service wherever it was on.** The jail's sysfs is a fresh one, without selinuxfs mounted under it, so `/sys/fs/selinux/enforce` was never there. Without it, selinux asks `/proc/filesystems`, which lists selinuxfs only where SELinux is enabled: `node_selinux_enabled` is 1 there, without `node_selinux_current_mode`, which only enforce tells; 0 only where the kernel has no SELinux.
- hostapd_stations wrote 0 for a byte or packet count hostapd did not give a station, which Prometheus takes for a counter reset; it leaves the sample out.
- **A failed netlink request said nothing of why**: on a real access point, `collector 'netdev': RTNL_FAILED`, `collector 'wifi': NL80211_FAILED (phy0-ap0: null)` and `collector 'netclass': SOURCE_INVALID (RTM_GETLINK: false)`. ucode's rtnl and nl80211 clear their error as `error()` reads it, and the capability read it twice; a request the kernel refused, which they answer with `false`, was taken for a reply. The capability reads the error once and fails a `false` reply too, so the log says why, as `RTNL_FAILED (Operation not permitted)`.
- **Counters from ubus went negative past 2^31.** ucode's ubus gives a 32-bit integer signed, whatever the daemon meant: dnsmasq's metrics could read `-2147483000`, hostapd_stations' packet counts too, and an odhcpd lease that never expires (`valid` of (uint32_t)-1, given as -1) got an expiry a second before the scrape, as if it had expired. dhcp_leases' `iaid` past 2^31 was labelled negative. Each is read unsigned, with the API's new `u32()`; wireguard uses it and `u16()` where it had its own.
- **filesystem exported nothing in the service, and said it succeeded.** It joined luci's `getMountPoints` with `/proc/self/mounts`, which in the service's jail is the jail's own mount table: on a router no mount matched, and `ucode_prometheus_exporter_collector_samples{collector="filesystem"}` was 0. It reads the host's `/proc/mounts` through rpcd's file object (`ubus call file read`), which luci-base, already its package's dependency, installs. The read-only flag is the host's mount's, no longer the jail's.
- **A program a collector started outlived the collector.** Its child process, killed at the collector's budget or the deadline, was killed alone, and what it started ran on: three scrapes of a collector that ran `system('sleep 100')` left three `sleep`s. The scrape now kills the child with every process under it, as the program watchdog does. **BREAKING** for collectors: the loader and `collector check` refuse a collector that calls `system`, pointing at `deps.exec`, or `include`, which loads code as `require` does.
- **A full state directory was logged as a failure to fork.** When the file a scrape's collectors hand their runs back by could not be made, the log said `cannot fork a process to run the collectors in`. Each failure now says its own: `cannot make the file the collectors' runs cross by, in <directory>`.
- **Doubles lost precision.** A value that is a double was written with ucode's 14 significant digits, so a timestamp with sub-second digits or a byte count past 10^14 read back as another number. A double is now written with as few digits as read back as itself, 17 at most: `1790874600.3102953`, where it was `1790874600.3103`. Integers, `NaN` and `±Inf` are written as before.
- **The ledger could stop being written.** A collector's own error code was kept at any length, and past the state's 32 KiB the write was refused, silently: durations, breakers and counts froze, and a quarantined collector stayed quarantined. A code that is not an uppercase word of at most 64 characters is counted as `OTHER`; a ledger still too large is written without the breakers' reasons and the failures by code; and a scrape that cannot record itself says so, at warning.
- **A collector could log without end.** 5,000 calls of `deps.log` in one run were 5,000 lines, enough to flush logd's ring of every other daemon's. A run's log now takes 10 lines of 512 bytes at most, and then says in one line how many more it left out.
- **A collector that failed without an error code was quarantined at once.** A code the collector API does not export, as `errors.COLLECTOR_CRASHED`, is null, and the child process handed such a failure back as `COLLECTOR_KILLED`, which trips a breaker; the tests' in-process runner kept the null. Both now fail it with `COLLECTOR_NO_RESULT`, which counts as one failure.
- **Two child processes that died anywhere in a scrape failed every collector left as `COLLECTOR_KILLED`**, and tripped their breakers, though none of them had run. The count is of children that die in a row before running a collector, and starts again once one runs one; when it gives up, the rest fail with the new code `COLLECTOR_NOT_RUN`, logged once for all, which leaves their breakers as they were.
- **A collector the deadline left out was never measured again.** It was not run, so not timed, and one slow run could keep it out for the instance's life. Each scrape that leaves it out now makes its estimate three quarters of itself, so it is tried, and timed, again after a few: see [About deadlines and circuit breakers](docs/explanation/deadlines-and-breakers.md#trade-offs).
- **A collector that wrote over its `deps` changed them for the collectors after it.** `deps.fs` and `deps.ubus` were one object for the whole scrape; each run now gets its own. What the collector API exports stays shared, and read-only by contract: see [About the architecture](docs/explanation/architecture.md#the-loader).
- **One collector could make Prometheus refuse the whole scrape.** A label value or HELP text that is not valid UTF-8 (a Latin-1 SSID or hostname from a LAN client), two label names that are one once sanitized (`if-name` and `if_name`), or a string passed where the labels go, which was written as it was: Prometheus refused the reply, and `up` was 0 for every collector. The recorder now stops such a collector at that sample, as at its `max_samples`, and it fails alone with `EXPOSITION_INVALID`, naming the family and the label; none of its samples are served. textfile's `*.prom` files are held to the same. **BREAKING** for collectors: what goes where the labels go is an object, null, or what `out.labels()` made, and nothing else; a label set spliced by hand fails.
- **A scrape spent nearly as long besides its collectors as in them.** Each collector's settings read the main section of the config two or three times over, and each value of a range option made its datatype anew: on the NanoPi R3S a scrape of 37 collectors took 0.79 to 0.89 s through uhttpd, 0.47 s of it collectors. A scrape now reads the main section once, a range is made once, and what was done for each family is done in one pass; on QEMU's 500-MIPS MIPS 24Kc a scrape of the `-full` group takes 1.16 s where 0.2.0 took 1.44 s, and 0.59 s besides its collectors where 0.2.0 took 0.87 s. Nothing waited on a timer: see [Performance on small routers](docs/explanation/performance.md#besides-the-collectors).
- **uhttpd kept six descriptors open for each collector.** Each collector was compiled as a program of its own, with its own copy of the collector API and the modules behind it, whose source files ucode keeps open: 268 descriptors for 37 collectors on the R3S, toward the limit of 1024. The collectors are compiled as one program, once each has loaded in a child process of its own: one descriptor each, and the API's once. Loading them takes 0.37 s on the 24Kc where it took 0.93 s, and uhttpd holds 3.5 MB where it held 5.2 MB. A collector that writes over what the API exports would now write over it for the others; none has a reason to.
- **The install guide left out the feed.** The base package depends on `ucode-docopt`, which OpenWrt's feeds do not have, so its `apk add` failed on a device without the exporter's feed. [How to install the exporter](docs/how-to/install.md) adds the feed and its key first, as the README and the tutorial do, and its `.apk` example names `ucode-docopt` and no stale version.
- **`hash-password` at a terminal dropped the spaces a password starts or ends with**, so the hash took another password than the one typed. It keeps them now, as it did from standard input: either way only the CR and LF that end the line go.
- **Basic auth failed open when its file was gone.** Should `/var/run/prometheus-exporter/uhttpd.conf` go while the service ran, and procd start uhttpd again as it was, the jail had no file to mount, and the handler served `/metrics` without a login. The handler now reads `auth_user` from the config, which the jail has, and denies every request while it is set and the file is not there, as it denies a file that is not right: `500`, logged at err. A restart writes the file again.
- **A `memory_limit` of 1 to 7 MB passed `check`, and uhttpd then crash-looped**: loading the handler takes 4 MB of data with the base package's collectors and 6 MB with all 45. `memory_limit` takes 0, a quarter of the RAM as before, or 8 MB and more, and refuses the rest with the new code `ZERO_OR_MIN`.
- **A renewed certificate was not picked up.** The jail kept the certificate and key the service started with, and a reload left the instance running, as their paths had not changed. A reload now restarts it when either file changed: see [How to serve HTTPS with basic auth](docs/how-to/https-basic-auth.md#renew-the-certificate).

## [0.2.0] - 2026-10-08

A slow or broken collector now costs only itself: a scrape answers within the scraper's timeout, runs each collector in a process of its own, and quarantines one that hangs, overruns or keeps failing. Upgrading from 0.1 takes a few steps: see [Upgrading the exporter](https://m00qek.github.io/ucode-prometheus-exporter/0.2/how-to/upgrade/#from-01-to-02).

### Added

- **A deadline per scrape.** A scrape answers within the timeout the scraper sends in `X-Prometheus-Scrape-Timeout-Seconds`, as Prometheus and vmagent do, less half a second; without it, within the new option `scrape_timeout`, 10 seconds. A collector the deadline has no time left for is left out, and a program still running at it is killed: both fail with `SCRAPE_DEADLINE`, logged once a scrape, at warning. See [About deadlines and circuit breakers](https://m00qek.github.io/ucode-prometheus-exporter/0.2/explanation/deadlines-and-breakers/).
- **Fastest first.** Each instance keeps a ledger of how long each collector takes, and a scrape runs the collectors fastest first, those it has not timed yet last, so a slow one no longer takes the ones after it with it. The reply keeps its order. The ledger is in RAM and a restart forgets it.
- **Circuit breakers.** A collector whose program is killed at its timeout, that takes longer than its budget, or that fails three scrapes in a row is quarantined: not run for 1 scrape, then 2, 4, up to 32, and tried again after each. The budget is the new option `collector_budget`, 5 seconds, or a collector's own `budget`. A quarantined collector fails with `COLLECTOR_QUARANTINED`, and `ucode_prometheus_exporter_collector_quarantined{collector}` is 1. `service prometheus-exporter check`, the ubus object's `status` and LuCI's status page say which collectors the service quarantined or left out, and why.
- **The `exporter` collector**, in the base package: the exporter itself, as Prometheus's client libraries describe a process (`process_cpu_seconds_total`, `process_resident_memory_bytes`, `process_open_fds`, ...), and what went wrong in its scrapes since it started: `ucode_prometheus_exporter_scrapes_total`, `_auth_failures_total`, `_collector_failures_total{collector,reason}`, `_program_timeouts_total`, `_quarantines_total`, `_deadline_skips_total`, and each collector's `_collector_samples` of the scrape.
- **Containment.** One collector can no longer impair the others or the service. See [Collector contract](https://m00qek.github.io/ucode-prometheus-exporter/0.2/reference/collector-contract/).
    - Each scrape runs its collectors in a child process, which is killed under one that is still running at the end of its budget: a loop that never ends or a system call that never returns fails that collector alone (`COLLECTOR_CANCELLED`), and the rest run in a new child. A child that dies under a collector, past the memory limit or in a native crash, fails it alone too (`COLLECTOR_KILLED`).
    - A collector writes at most `max_samples` samples a scrape, a new main option of 20,000, or its own: past it, it fails with `SAMPLE_LIMIT`, and none of its samples are served.
    - A metric family belongs to one collector, the exporter's own first: another that writes it fails with `FAMILY_CONFLICT`, and so does one that writes `node_scrape_collector_*` or `ucode_prometheus_exporter_*`.
    - A scrape keeps a progress file: the next scrape quarantines the collector a scrape process that died was running, and kills the child it left behind.
    - Every collector module is loaded in a child process first, for 5 seconds at most, when uhttpd starts: one that never returns is left out, logged at err, and the rest load.
    - The new option `memory_limit` limits the memory each of the service's processes may take: by default a quarter of the RAM, at most 64 MB. The service runs at nice 10, below hostapd, dnsmasq and netifd.
- `check`, the ubus object's `status` and `prometheus-exporter scrape` run the collectors in the service's jail, as Prometheus's scrapes do, where ujail can run; the `status` reply says whether it did in the new field `jailed`.
- The command's new subcommands: `collector check <path>`, which loads a collector not installed yet, runs it under the scrape's guards and says which rule of the contract it broke; `hash-password`, which reads a password without echo and prints the hash `auth_password` takes; and `--version`. See [The prometheus-exporter command](https://m00qek.github.io/ucode-prometheus-exporter/0.2/reference/command/).
- **The collector API**, `prometheus_exporter.api`: the one module a collector imports, which exports `Result`, `errors`, `services`, `proc` and `exposition`. What it exports is what a major version protects for collectors; the modules behind it may change in any release. `proc.auxv()` reads the auxiliary vector for any collector.
- What a collector may declare: `meta.max_samples`, its own sample limit (nat_traffic's is 65,536), and `meta.cost: 'heavy'`, which runs it after the others while the ledger has not timed it.
- A collector's tests, through `with_collector`, run it in the filesystem its jail gives it, and fail when it reads a path, opens a socket or runs a program its meta does not declare, which the service's jail would not have.
- **Typed doc comments.** Every export of the exporter's modules has a JSDoc block, with its types, which ucode-language-server shows on hover and checks calls against: a collector's `deps`, `out` and `options`, and what the API exports.
- How-to: [Pushing metrics from the router](https://m00qek.github.io/ucode-prometheus-exporter/0.2/how-to/push-metrics/), to a Pushgateway or VictoriaMetrics from cron. Reference: [Collector contract](https://m00qek.github.io/ucode-prometheus-exporter/0.2/reference/collector-contract/). The security explanation states the threat model: collectors are buggy, not hostile.
### Changed

- **BREAKING: the command line takes subcommands**, parsed by docopt from its usage text: `prometheus-exporter [COLLECTOR...]` is `prometheus-exporter scrape [COLLECTOR...]`, and `prometheus-exporter -l` is `prometheus-exporter collector list`. The base package depends on `ucode-docopt`.
- **BREAKING for collectors: a collector imports `prometheus_exporter.api` and nothing else**, and calls neither `require`, `loadfile` nor `loadstring`; the loader leaves out one that does, logged at err with what to use instead. Its capabilities in `deps` do what it imported `fs`, `ubus` or `uci` for. Every collector of the exporter's packages does already; one written for 0.1 takes `Result`, `errors` and `proc` from the API, and `proc.first_line()` for `first_line()`.
- **BREAKING for collectors: a collector module is in strict mode**, `'use strict'` its first statement; the loader leaves out one that is not.
- **BREAKING for collectors: each option of `meta.options` has a `title`**, a label of 1 to 40 characters in sentence case, as `title: 'Excluded devices'`; the loader leaves out a collector with an option that has none, logged at err. LuCI's Edit dialog labels the option by it, untranslated, where it showed the option's name; the core's options of a collector are labelled by LuCI, translated (Program timeout, Budget, Sample limit). The ubus object's `collectors` gives each option's `title`. Every collector of the exporter's packages has them.
- **BREAKING: the ubus object's `validate` answers each value it refuses with an object, not a sentence**: a code of a closed set, its arguments and the English as `message`, as `{ "code": "RANGE", "min": 1, "max": 65535, "value": 0, "message": "expected an integer from 1 to 65535, got 0" }`. The codes are listed in [UCI configuration](https://m00qek.github.io/ucode-prometheus-exporter/0.2/reference/uci-config/#problems). LuCI says each in the user's language, naming the field by its title, and shows `message` for a code it does not know. `check`, the log and the command line print the English they printed.
- A collector's package no longer depends on what it watches: those of mwan3, chrony, modemmanager, ubnt-manager and wireguard installed mwan3, chronyd, ModemManager, ubnt-manager and rpcd-mod-wireguard. Where it is not there, the collector has nothing to observe. An upgrade removes nothing that was installed.
- The exporter's modules are split into smaller ones, behind facades (`config/`, `deps/`, `exposition/`, `loader/`, `rpc/`), with no change of behaviour; the package installs their directories.
- The state of an instance is written under a lock, so concurrent requests, a scraper, LuCI and curl, each update it whole.
- LuCI's status page says what needs attention in a banner above the tables: the service enabled and not running, switched off, collectors failed or quarantined. The rows are grouped worst first, and the page's own scrape, the Test run, is a column apart from the Service's scrapes.
- LuCI's settings split the Exporter tab into General, HTTPS & login and Limits, and the Limits tab takes `scrape_timeout`, `collector_budget` and `max_samples`.
- LuCI: a refused Save opens LuCI's own error dialog, wherever the page is scrolled, naming each field by its tab with a link to it; the Edit dialog's text is legible in every theme, and the focus returns to Edit when it closes; a read-only login can open Edit; the collectors are listed by title.

### Removed

- **BREAKING: the `wifi_stations` collector and its package.** It wrote the families `wifi`'s option `stations` writes, so each station was exported twice; `wifi`'s stations, on by default, are what it was. Remove `ucode-prometheus-exporter-wifi_stations` before upgrading.

### Fixed

- textfile no longer hangs on a FIFO named `*.prom`: it reads regular files alone, and counts any other in `node_textfile_scrape_error`.
- textfile found no files in the service when its `directory` option ended in a `/`: the jail now mounts it.
- Two requests writing the instance's state at once could leave a half-written file in place.
- LuCI showed a raw `RPCError` and its stack trace while rpcd restarts; it now says in words that the exporter's ubus object is not available, and the page is read-only until it is.

## [0.1.0] - 2026-10-01

The first release: a rewrite of the packages feed's `prometheus-node-exporter-ucode` and `prometheus-node-exporter-lua` for OpenWrt 25.12, served by uhttpd at `/metrics` on port 9100. See the [documentation](https://m00qek.github.io/ucode-prometheus-exporter/0.1/).

### Added

- 45 collectors, the ucode exporter's and the Lua exporter's ported alongside, under node_exporter's metric names: 15 in the base package, each other a package of its own, with the `-network`, `-wireless`, `-hardware` and `-full` groups. The [renamed metrics](https://m00qek.github.io/ucode-prometheus-exporter/0.1/metrics/) say what the feed's names became.
- A jail for the service, built from what each collector declares it reads and runs.
- HTTPS and basic auth, with the password stored as a crypt hash of at most 2000 rounds; a header let in once is let in again without computing the hash. gzip when the scraper asks, `http_keepalive` (0 closes each connection), and leaving out counters that are 0.
- The import of a feed exporter's settings on first install.
- WireGuard peers named by their description only with the `peer_names` option, read through rpcd, so the jail never holds the private keys.
- A ubus object, `prometheus-exporter`, which the LuCI app, `luci-app-prometheus-exporter`, uses for its settings and status pages.
- The documentation site, in the Diátaxis structure, published per minor version.
