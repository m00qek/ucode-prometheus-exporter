    How to Troubleshoot¶

    Start from what is wrong: the service, one collector, or the scrape as Prometheus sees it. Each section below covers one case.

    The service does not run¶

    Open Status → Prometheus exporter. A banner above the tables says whether the exporter is enabled but not running, or switched off in its settings. Its System log button opens Status → System Log: look for the lines with prometheus-exporter.

    service prometheus-exporter status
logread -e prometheus-exporter

    If the exporter is switched off, turn it on: in LuCI, tick Enable on the General tab of Services → Prometheus exporter and press Save & Apply, or use the SSH commands in the table's first row.

    status or the log says Do
    disabled (option enabled in /etc/config/prometheus-exporter) uci set prometheus-exporter.main.enabled=1, commit, service prometheus-exporter start.
    invalid configuration, not starting, after the lines that say why Fix the option it names: service prometheus-exporter check shows the same as FAIL lines. See UCI configuration.
    deferring start until listen interface <name> becomes ready The interface has no address yet. It starts once it has one; check ifstatus <name>, or listen elsewhere: How to listen on the LAN.
    basic auth takes HTTPS only, and <cert> or <key> is missing: not starting The TLS files are not there. See How to serve HTTPS with basic auth.
    cannot make <path>: <error> The service could not make a directory: tmpfs is full, or the path is wrong.

    If you reload with an invalid configuration, the service keeps the running exporter and logs invalid configuration, keeping the running instance.

    A collector fails¶

    Run a scrape, and see for each collector whether it succeeded, failed, or had nothing to observe, and why:

    Open Status → Prometheus exporter. Failed collectors come first. Test run says Failed with why and its error code, or Nothing to observe with why.

    service prometheus-exporter check

    warn scrape: dnsmasq: UBUS_CALL_FAILED (dnsmasq metrics: Not found)
ok   scrape: wifi has nothing to observe: no wireless radios
    • Nothing to observe is not a failure. It means the device lacks the hardware, kernel feature or running service the collector reads. The collector succeeds without samples, and its node_scrape_collector_observing is 0. If you do not want the collector, disable it. Collectors lists when each collector has nothing to observe.

    • A failure has a code: a warn line of check, or Failed in LuCI. Error codes says what each code means. Under procd, the service also logs each failing scrape at warning:

      logread -e prometheus-exporter | grep "collector '"

    The ubus object's status shows the same:

    ubus call prometheus-exporter status

    A collector is quarantined¶

    The service quarantines a collector when:

    • the exporter killed its program at its timeout,
    • it was still running at the end of its budget (the time it may take),
    • its process ended under it, or
    • it failed three scrapes in a row.

    The service then leaves the collector out for a few scrapes, and tries it again. Meanwhile, its node_scrape_collector_success is 0 and its ucode_prometheus_exporter_collector_quarantined is 1. check says why, and when the service tries it again:

    warn service: nat_traffic is quarantined: COLLECTOR_OVERRUN (took 7.84 s, over its budget of 5 s); the service tries it again in 8 scrapes, or at once once restarted
    1. Fix what tripped it. check runs the collector now, and its warn scrape: line says how it fails.
    2. If the collector is slow but you want it, raise its budget. In LuCI, press Edit on its row of the Collectors tab, set Budget, press Save, then Save & Apply. Over SSH: uci set prometheus-exporter.<module>=collector, uci set prometheus-exporter.<module>.budget=15, commit, reload_config. If a program is slow, raise its timeout: see How to give programs more time.
    3. To try it at once rather than wait for its trial, run service prometheus-exporter restart. A restart forgets every quarantine.

    LuCI's Status → Prometheus exporter page shows the same in its Service's scrapes column, and names the quarantined collectors in a notice above the tables. The exporter collector counts quarantines since the service started, in ucode_prometheus_exporter_quarantines_total{collector}.

    A collector breaks the contract¶

    The log says collector '<name>': followed by one of the errors below. Only that collector fails. The exporter serves every other collector as before.

    Error What happened Do
    COLLECTOR_CANCELLED It was still running at the end of its budget, and was stopped with its process: a loop that never ends, or a read that never returns (a FIFO, a socket). If it is only slow, raise its budget; otherwise it is a bug of the collector.
    COLLECTOR_KILLED Its process ended under it: past the memory limit, a crash, exit(); or its scrape process died while it ran, collector '<name>' was running when a scrape process died. Raise memory_limit if it is only large; otherwise it is a bug.
    SAMPLE_LIMIT It wrote more than its max_samples: the detail says how many, and in which family. If its output is that large on this device, raise its max_samples.
    EXPOSITION_INVALID It wrote what Prometheus would refuse the whole scrape for: a label value or HELP text that is not valid UTF-8 (a Latin-1 SSID or hostname), or two label names that are one once sanitized. The detail names the family and the label. A bug of the collector, which should make the value valid or leave it out.
    FAMILY_CONFLICT It wrote a family another collector writes, or one the exporter keeps for itself: the detail names it. Disable one of the two, or fix the collector's names.
    hung at load (at err) Its module's top level did not return in 5 s: it is left out until the service restarts. A bug of the module.
    COLLECTOR_IMPURE (at err) Its module's top level called what only collect() may, as sleep() or print(): it is left out until the service restarts. prometheus-exporter collector check <file> names the line. A bug of the module: see The top level.

    prometheus-exporter collector check <module file> (from ucode-prometheus-exporter-cli) runs a module as the service would, and says which rule it breaks: see Collector contract.

    Collectors are left out at the deadline¶

    A scrape ran out of the time the scraper gives it. The log says scrape deadline: <n> collectors not served in its <seconds> s: ..., and check says the scrape deadline left <name> out. Collectors run fastest first, so the ones left out are the slowest.

    • Leave the slow collector out of this job, with params: { 'exclude[]': [ nat_traffic ] }. Scrape it in a job of its own with a longer scrape_timeout, and a budget to match.
    • Or raise the job's scrape_timeout. Prometheus sends it with each scrape.
    • If a scraper does not send X-Prometheus-Scrape-Timeout-Seconds, the exporter uses the main section's scrape_timeout, 10 seconds.
    • ucode_prometheus_exporter_deadline_skips_total{collector} counts the skips since the service started.

    See About deadlines and circuit breakers.

    A collector works in check and fails under procd¶

    check, the ubus object's status, LuCI's status page and prometheus-exporter scrape run the collectors in the service's own jail, as Prometheus's scrapes do. So they see what Prometheus gets.

    Where ujail cannot run, they run the collectors outside the jail, as root, and check says scrape, outside the jail. A collector that works there and fails under procd needs something the jail does not give it.

    1. See what the jail gives it:

      service prometheus-exporter check | grep '^warn jail'
ubus call service list '{"name":"prometheus-exporter"}'

      check warns about a path or program it cannot mount. procd's list shows what it mounted.

    2. If a path was missing when the service started, the service mounts it once it appears. check says <path> is not there; the service mounts it once it is, and the watch instance reloads the service when the path appears. To mount it at once, run service prometheus-exporter restart.

    3. A program that is not installed shows as a jail: <collector>: command <name> is not on ... warning. Install its package.

    The jail lists what the jail holds.

    Prometheus cannot scrape it¶

    Prometheus says Do
    connection refused The exporter does not listen where Prometheus asks. service prometheus-exporter status says where it listens; by default, loopback only. See How to listen on the LAN.
    A timeout The firewall drops it, or the scrape is slow: the exporter answers within the timeout the scraper sends, but not on the first scrape after a restart, before it knows how long each collector takes. A timeout scrape after scrape is a scraper that sends none: set scrape_timeout to its timeout.
    400 Bad Request The scrape's collect[] names a collector that is not installed, or is disabled. The body says which.
    401 Unauthorized The user or password is wrong.
    server returned HTTP status 403 Forbidden Basic auth is on and the request came over HTTP: use scheme: https.
    500 Internal Server Error Basic auth's file is broken, or gone while auth_user is set: service prometheus-exporter restart writes it afresh.

    The metrics are not what you expect¶

    • A name differs from the feed's exporters: see Renamed metrics.
    • A label is missing: a collector leaves out a label it has no value for.
    • Counters that are 0 are missing: option omit_zero_values '1' leaves them out.
    • To see how the scrape went, read what each collector reports about itself: node_scrape_collector_success is 0 for a failure, node_scrape_collector_observing is 0 for nothing to observe, and node_scrape_collector_duration_seconds is the time each took.

    This query alerts on a failing collector, and ignores one with nothing to observe:

    node_scrape_collector_success == 0

    The bundled rules alert on it, and on the rest of the exporter's health: see How to monitor a router with the bundled dashboards and alerts.
