    Migrate from prometheus-node-exporter-lua/-ucode¶

    This page maps each package and each metric family of the packages feed's exporters to what this exporter has in its place. It also shows how to carry queries, recording rules and the configuration over.

    make docs-gen writes the tables from two sources: the feed exporters' own sources, prometheus-node-exporter-lua 2026.06.05-r1 and prometheus-node-exporter-ucode 2024.02.07-r2, from openwrt/packages@705e1cc3beb7a0cb3ef53ba18a3ba1fed8f4342c (which make feed-inventory reads), and what this exporter's collectors write, as Metrics lists it. The generator refuses a family of the feed's exporters that has no row here.

    The steps are in How to move from the feed's exporters. Why the names changed is in Renamed metrics and About metric names.

    Summary¶

    Each family of each exporter, by what it is here:

    • same: the same name and labels;
    • renamed: another name;
    • relabeled: the same name with other labels, or with other values of them (cpu="0" for cpu="cpu0");
    • missing: nothing here writes it.

    A family of a collector whose name is computed (meminfo's node_memory_<Field>_bytes) counts once.

    Change Lua exporter's families ucode exporter's families
    same 93 65
    renamed 91 24
    relabeled 23 8
    missing 4 0
    all 211 97

    There is no option to write the old names. For a fleet that runs both exporters for a while, see A transition.

A package of the same name has this exporter's prefix, ucode-prometheus-exporter, and the same suffix: prometheus-node-exporter-lua-nat_traffic is ucode-prometheus-exporter-nat_traffic.     These packages have no counterpart in the feed:

    • ucode-prometheus-exporter-cli, the prometheus-exporter command. It prints a scrape on standard output, and checks the configuration and a collector module. The feed's exporters had their command in the base package (/usr/bin/prometheus-node-exporter-lua and -ucode, a scrape on standard output). Here the service needs none of it, and service prometheus-exporter check belongs to the base package. Install it for cron jobs that push a scrape: see How to push metrics.
    • The groups, ucode-prometheus-exporter-network, -wireless, -hardware and -full, which install several collectors: see How to choose collectors.
    • luci-app-prometheus-exporter, the LuCI app, and ucode-prometheus-exporter-devkit, which a collector of another package is written and tested with.
    • The collectors the feed had none of: ucode-prometheus-exporter-agh, ucode-prometheus-exporter-chrony, ucode-prometheus-exporter-dhcp_leases, ucode-prometheus-exporter-diskstats, ucode-prometheus-exporter-interrupts, ucode-prometheus-exporter-mmc, ucode-prometheus-exporter-pressure, ucode-prometheus-exporter-qdisc, ucode-prometheus-exporter-sockstat.

    A query that selects collectors still works: collect[]= as the Lua exporter has it, and collect= as the ucode one does. Name a collector as here (nft-counters, ltq-dsl), or by its module (nft_counters). wifi_stations is refused: wifi writes the stations.

    Metric families¶

    The families are grouped by the feed's collector. The columns:

    • Lua and ucode: the labels each exporter writes the family with, or — where it does not write it.
    • Here: the family or families that take its place, with the labels this exporter writes them with, as the captures show them. A label written only with an option is among them.

    A type that changed is in the notes.

    PromQL¶

    How the most common queries and recording rules on the old names read now. The values are the same unless the notes above say otherwise.

    Wi-Fi. The wifi_ families are node_exporter's node_wifi_ families, with these labels:

    • radio: the wifi-device (the Lua exporter's device);
    • device: the interface (the Lua and ucode exporters' ifname);
    • mac_address: a station (was mac).

    Only node_wifi_network_info has the network's SSID and BSSID:

    # was: wifi_network_signal_dbm{ssid="home"}
node_wifi_network_signal_dbm * on (radio, device) group_left (ssid) node_wifi_network_info{ssid="home"}

# was: sum by (ifname) (wifi_stations)    (Lua's wifi_stations)
sum by (device) (node_wifi_stations)

# was: wifi_network_quality > 50          (a percentage)
node_wifi_network_quality_ratio > 0.5

# was: rate(wifi_station_receive_bytes_total{mac="..."}[5m])
rate(node_wifi_station_receive_bytes_total{mac_address="..."}[5m])

    hostapd stations. The network's labels are on hostapd_station_info, one series per station:

    # was: hostapd_station_signal_dbm{ssid="home"}
hostapd_station_signal_dbm * on (vif, station) group_left (ssid) hostapd_station_info{ssid="home"}

    NAT traffic. There is a series per host on this side of the router, where there was one per pair of addresses:

    # was: sum by (src) (node_nat_traffic)
node_nat_traffic_bytes

# was: topk(10, node_nat_traffic)         (pairs)
topk(10, node_nat_traffic_bytes)          # hosts; the pairs need the option peers

    CPU. cpu is the CPU's number, and guest time is counted apart:

    # was: sum by (cpu) (rate(node_cpu_seconds_total{mode!="idle",cpu="cpu0"}[5m]))
sum by (cpu) (rate(node_cpu_seconds_total{mode!="idle",cpu="0"}[5m]))

    Gauges that ended in _total. node_procs_running, node_procs_blocked and dawn_ap_stations no longer end in _total. The counters nft_counter_packets_total and nft_counter_bytes_total now do. A rate() of one of the old gauges was a mistake, and still is.

    Units. A family whose unit changed is a renamed family. The Lua exporter's wifi_network_bitrate, in kbit/s, is node_wifi_network_transmit_bits_per_second, * 1000. ModemManager's and bmx7's percentages are ratios, / 100. A recording rule keeps an old dashboard working until it is changed:

    groups:
  - name: feed-exporter-names
    rules:
      - record: wifi_network_bitrate
        expr: label_replace(node_wifi_network_transmit_bits_per_second / 1000, "ifname", "$1", "device", "(.*)")
      - record: wifi_network_quality
        expr: label_replace(node_wifi_network_quality_ratio * 100, "ifname", "$1", "device", "(.*)")
      - record: node_nat_traffic
        expr: label_replace(node_nat_traffic_bytes, "src", "$1", "host", "(.*)")

    unbound. Each counter is per thread, labeled thread, as letsencrypt/unbound_exporter writes them: sum without (thread) (unbound_queries_total) is the Lua exporter's unbound_num_queries_total.

    Is the collector there? node_scrape_collector_success == 0 still finds a collector that failed. But a collector whose service or hardware is not there succeeds here, with node_scrape_collector_observing 0, where the Lua exporter failed it. See About nothing to observe.

    The configuration¶

    When the package is installed, its uci-defaults script takes over the settings of /etc/config/prometheus-node-exporter-ucode, or, without it, of /etc/config/prometheus-node-exporter-lua. It writes them into /etc/config/prometheus-exporter, once, and logs what it did (see Log messages).

    • It does so only while /etc/config/prometheus-exporter is as the package ships it.
    • It leaves the old file as it was.
    • apk keeps a feed exporter's config at removal only if it was changed, so what there is to take over is what someone set.
    Old setting Taken over?
    listen_interface, listen_port, http_keepalive, cert, key, omit_zero_values of the main section Yes, each whose value this exporter accepts. A value it would refuse is left at its default, and logged. A port that is the old exporter's default (9101 for the ucode one, 9100 for the Lua one) becomes 9100.
    The ucode exporter's config collector sections (wifi's stations) Yes, each named section, with each option checked as the service checks it. An option the collector does not have is left out, and a value it refuses is left at its default; each is logged, so the configuration stays valid. The script runs as the base package is installed, before the packages installed with it. So a collector not installed yet is checked against the options the feed's ucode exporter had for it (wifi's stations), and the options every collector has (enabled, budget, max_samples).
    Both old configs Only the ucode exporter's.
    Which collectors were installed No: install the packages of Packages.
    Whether the old service was enabled No: the exporter is enabled when it is installed.
    The Lua exporter's textfile directory Nothing to take over: textfile reads /var/prometheus by default, as the Lua exporter did.
    WireGuard peer descriptions No: the old exporters always labeled peers with their description; here, only with wireguard's option peer_names.
